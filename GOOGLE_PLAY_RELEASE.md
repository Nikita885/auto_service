# МойАвтоСервис: подготовка Google Play

Проверено по официальным правилам 15 ноября 2026 года. Техническая подготовка не означает одобрение модерацией. Домен остаётся `https://moi-servis.ru`, идентификатор Android — `ru.autoservice.client`: их смена сейчас не выполнялась.

## Реализовано в проекте

- Название «МойАвтоСервис», поддержка +7 (3519) 48-12-12, nic84062@gmail.com. Владелец: Жизнин Никита Сергеевич.
- targetSdk/compileSdk 36, версия 2.1.0 / versionCode 3, AGP 8.13.2, Gradle 8.14.3, JDK 17.
- Камера запрашивается только при сканировании QR, не обязательна для установки. Можно ввести код вручную. Широкого доступа к файлам, контактам, SMS и геолокации нет.
- Политика: `/privacy/`. Запрос удаления из профиля и публичный путь через браузер: `/delete-account/`. Браузерная версия работает без установки, включая Android.
- Заявки удаления находятся в Django-админке → «Заявки на удаление аккаунтов». Администратор выполняет действие «Удалить данные по выбранным заявкам». Активные визиты и несверенные расчёты сначала урегулируются; заявка остаётся в очереди. После обработки локальные контактные данные, гараж и дневник удаляются, сессии отзываются; сохраняется обезличенный журнал расчётов и обязательные финансовые документы. Это не просто отключение входа.
- Для ответов ИИ есть кнопка «Сообщить о проблеме», жалобы рассматриваются в админке. Присланный пользователем текст ответа сохраняется только после подтверждения жалобы.
- Production не раскрывает OTP ни общей настройкой, ни списком отладочных номеров. Зашифрованы токены и кеш клиента на Android; резервное копирование приложения отключено.
- Добавлены браузерные проверки и Android build/lint/unit tests в CI.

## До отправки релиза — действия владельца

1. **Утвердить политику данных.** Проверить реквизиты, фактических провайдеров SMS/звонков, YandexGPT и Sentry, основания/сроки хранения рабочих и финансовых документов, срок обработки удаления, бэкапы и удаление из внешней 1С. Юридический адрес не предоставлен и не придуман. Доступные страницы — техническая основа, а не юридическое заключение. После утверждения установить `PRIVACY_POLICY_APPROVED=true`.
2. **Наладить обработку удаления.** Назначить ответственного, регулярно проверять очередь, согласовать срок ответа и удаления. Действие в админке обрабатывает только данные этого сервера: 1С, провайдеры, логи и резервные копии требуют отдельного регламента. До этого процесс нельзя объявлять полностью готовым.
3. **Подписать AAB.** Настроить `RELEASE_STORE_FILE`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD` вне Git, включить Play App Signing. После первой загрузки versionCode необходимо повышать для каждого следующего релиза. Артефакт CI без этих секретов не подписан и не готов к загрузке как финальный релиз.
4. **App Links.** Заполнить `ANDROID_CERT_FINGERPRINTS` отпечатком сертификата подписи приложения из Play Console, не upload-сертификата. Проверить `/.well-known/assetlinks.json` на текущем домене. При смене домена отдельно обновить сборку, manifest/strings, сервер, TLS и правила редиректа.
5. **App access.** Предоставить модератору рабочий воспроизводимый доступ и инструкции на английском. Вход по звонку/одноразовому SMS может быть недоступен проверяющему. Подготовить безопасный тестовый сценарий/среду с синтетическими данными; не возвращать OTP в публичном API и не давать доступ к аккаунту реального клиента или сотрудника. Конкретные данные доступа владелец вносит в Play Console, в репозиторий их не кладут.
6. **Заполнить Play Console.** Data safety, политика по HTTPS, URL удаления, категория и рейтинг контента, целевая аудитория, декларация рекламы, контакты разработчика, страны, описание и снимки актуальной сборки. Подтвердить личность разработчика и выполнить требования, показанные именно этому аккаунту.
7. **Тестирование.** Для соответствующих новых личных аккаунтов требуется закрытый тест с минимум 12 участниками непрерывно 14 дней, затем запрос доступа в production. Пройти Pre-launch report, реальные Android-устройства, актуальную и старую WebView, большие шрифты, камеру, клавиатуру, App Links, обрывы сети и возвращение из фона. Проверка Chrome не заменяет проверку Android и iPhone.
8. **Проверить итоговый артефакт.** Изучить merged manifest и состав AAB, отсутствие отладочной конфигурации, подпись, target API, сторонние SDK и нативные `.so`. Код проекта — Java без NDK; это не отменяет проверки библиотек в финальном AAB на поддержку страниц 16 КБ.

## Основа декларации Data safety

Окончательные ответы зависят от фактической production-конфигурации и договоров с провайдерами. Нельзя автоматически выбрать «данные не собираются»: приложение передаёт телефон и данные записей серверу.

| Данные/функция | Что учитывать |
|---|---|
| Телефон, имя, UUID пользователя | Вход, обслуживание, защита от злоупотреблений; имя необязательно |
| Автомобили, госномер, VIN, пробег, дневник и комментарии | Пользовательский контент; поля заполняются пользователем, состав данных нужно явно раскрыть |
| История работ, чеки, расходы и бонусы | Покупки/финансовая информация в применимых разделах формы; приложение не запрашивает номер банковской карты для онлайн-оплаты |
| Вопросы подсказчику и жалобы | Сообщения передаются AI-провайдеру; подтверждённый текст жалобы сохраняется для модерации |
| IP, журналы входа/ошибок | Проверить хранение логов и технической диагностики, включая Sentry, если включён |
| QR-камера | Кадры обрабатываются на устройстве; приложение их не отправляет серверу |
| Install Referrer | Код приглашения из установки; проверить поведение SDK и состав финального manifest |
| Передача третьим сторонам | SMS/звонки, YandexGPT, Sentry при включении и 1С; в форме учитывать определения service provider и sharing, а не приравнивать все передачи автоматически |
| Удаление | Указать реальный процесс, исключения и сроки. Финансовые документы и бэкапы описать отдельно |

## Команды

```sh
# На сервере с действующей production-конфигурацией:
python manage.py security_audit --strict
python manage.py play_readiness

# Локально/в CI, JDK 17 и Android SDK 36:
cd mobile/android
./gradlew testDebugUnitTest lintRelease bundleRelease
```

`play_readiness` намеренно завершится ошибкой при неутверждённой политике, отсутствии сертификата App Links или небезопасных эффективных настройках. Он не проверяет состояние Play Console и не гарантирует прохождение модерации.
