# Мобильное приложение клиента (Android)

Клиент к API автосервиса: вход по SMS, знакомство с подсказками по маркам и
моделям автомобилей, запись на замену масла в четыре шага с живым таймером,
свои записи, приглашения с баллами и профиль. Java, Android Studio, без Kotlin.

**Минимум:** Android 7.0 (API 24). **Собирается под:** API 35.

## Быстрый старт

**Нужен JDK 17 или 21.** Gradle 8.9 новее 22 не понимает, а системный JDK на
машине разработчика может быть любым — Android Studio обычно приносит свой.
Если студии нет, подойдёт Temurin, распакованный куда угодно:

```bash
export JAVA_HOME=~/.jdks/temurin-21      # или org.gradle.java.home в gradle.properties
```

1. Откройте в Android Studio папку `mobile/android` (именно её, а не корень
   репозитория). Gradle-обёртка скачается автоматически при первом импорте.
2. Поднимите бэкенд: в корне репозитория `docker compose up -d`.
3. Запустите приложение на эмуляторе.

Проверено сборкой на AGP 8.7.2 / Gradle 8.9 / JDK 21: `assembleDebug` даёт APK
на ~6,8 МБ, `assembleRelease` с R8 и сжатием ресурсов — ~1,8 МБ.

### Кириллица в пути

Репозиторий лежит по пути `…/автосервис/…`, а Android Gradle Plugin на Windows
такие пути отклоняет:

```
Your project path contains non-ASCII characters.
```

В `gradle.properties` уже стоит `android.overridePathCheck=true` — для чистого
Java-проекта без NDK этого достаточно. Если сборка всё же упадёт на `aapt2` или
`R8` с невнятной ошибкой про путь, сделайте ASCII-ссылку и открывайте студию по
ней (cmd **от администратора**):

```
mklink /J C:\dev\autoservice-android "F:\автосервис\auto_service\mobile\android"
```

Это ссылка на ту же папку, а не копия: правки видны в git, синхронизировать
ничего не нужно. Та же причина, по которой в корневом проекте приходится
собирать `docker compose build api`, а не просто `build`.

**Unit-тесты из такого пути не запускаются вовсе.** Компиляция проходит, но JVM
тестового воркера читает classpath в системной кодировке Windows и не находит
классы — падает с `ClassNotFoundException` ещё до первого теста. Ни ASCII-ссылка
(сборка всё равно пишет в реальный путь), ни явный `-Dfile.encoding=UTF-8` не
помогают. Помогает вынос каталога сборки:

```bash
./gradlew testDebugUnitTest -PBUILD_DIR=C:/dev/asbuild
```

Флаг `BUILD_DIR` работает с любой задачей и по умолчанию не задан — на проекте
по обычному пути ничего менять не нужно.

### Адрес сервера

По умолчанию отладочная сборка ходит на `http://10.0.2.2:8000` — так эмулятор
видит `localhost` хост-машины. Для других случаев адрес задаётся снаружи, без
правки кода:

```bash
./gradlew assembleDebug -PDEBUG_API_URL=http://192.168.1.10:8000/ -PDEBUG_WS_URL=ws://192.168.1.10:8000/
```

Постоянное значение можно положить в `~/.gradle/gradle.properties` — тогда
студия будет собирать с ним без флагов:

```properties
DEBUG_API_URL=http://192.168.1.10:8000/
DEBUG_WS_URL=ws://192.168.1.10:8000/
```

| Где тестируете | Адрес |
|---|---|
| Эмулятор | `http://10.0.2.2:8000/` (по умолчанию) |
| Телефон в той же Wi-Fi сети | `http://<IP компьютера>:8000/` |
| Откуда угодно | `https://<домен туннеля>/` и `wss://<домен туннеля>/` |

Адрес из сборки — это только значение по умолчанию: в отладочной версии его
можно сменить в самом приложении, не пересобирая.

Открытый HTTP в отладочной сборке разрешён для любого адреса
(`src/debug/res/xml/network_security_config.xml`) — перечислить все возможные
IP заранее нельзя. В релизе действует основной файл, где cleartext запрещён;
подменить их местами не выйдет, Gradle берёт вариант по типу сборки.

### Туннель наружу

Нужен, когда телефон в мобильном интернете или в другой сети. Два рабочих
варианта:

```bash
bash tools/tunnel.sh          # порт 8000
bash tools/tunnel.sh 9000     # другой порт
```

Скрипт поднимает SSH-туннель, печатает адрес крупным блоком, дублирует его в
файл и сам переподключается после обрыва — бесплатные туннели рвутся по
таймауту. При первом запуске создаёт SSH-ключ: без ключа `localhost.run`
соединение принимает, но адрес не выдаёт вовсе.

Вручную то же самое:

```bash
ssh -i ~/.ssh/id_ed25519 -R 80:localhost:8000 nokey@localhost.run
ssh -R 80:localhost:8000 serveo.net          # альтернатива
cloudflared tunnel --url http://localhost:8000
```

**Если на машине работает VPN, перехватывающий весь трафик** (Meta Tunnel,
Radmin и подобные — в списке адаптеров у них адреса `198.18.x.x`), `cloudflared`
не подключится: сначала упрётся в `failed to dial to edge with quic` (UDP не
проходит), затем в `TLS handshake with edge error`. SSH-туннель в этих же
условиях работает — это обычный TCP-поток.

**Постоянного адреса на бесплатных тарифах нет.** Проверено: serveo выдаёт
новое имя при каждом запуске (резервирование требует регистрации),
`localhost.run` с ключом выдаёт адрес, но полагаться на его неизменность
нельзя. Поэтому адрес меняется прямо в приложении: на экране входа снизу
строка «Сервер: …». Кнопка есть только в отладочной сборке — в релизе адрес
один и зашит. Смена сервера сбрасывает вход: токены выдал прежний сервер, на
новом они недействительны.

Реализовано перехватчиком `HostInterceptor`, который подменяет схему, хост и
порт у каждого запроса. Retrofit задаёт базовый адрес при создании и потом его
не меняет, а пересоздавать весь стек ради смены хоста — терять пул соединений
и путаться в том, какой экран каким клиентом пользуется.

Код из SMS в разработке приходит прямо в ответе сервера (`OTP_DEBUG_EXPOSE_CODE=True`)
и подставляется в поле автоматически. В релизной сборке это поле игнорируется,
даже если сервер его пришлёт.

## Архитектура

MVVM в три слоя. Зависимости направлены внутрь: UI знает про домен, домен не
знает ни про кого.

```
ui/           экраны: Activity, Fragment, адаптеры, ViewModel
  auth/         вход по телефону и коду
  booking/      запись: четыре шага, таймер, живой канал
  bookings/     мои записи
  profile/      профиль и выход
  common/       Ui (ошибки, диалоги), Event (одноразовые события)

domain/model/ Models — то, чем оперируют экраны: даты, числа, готовые ответы
              на вопросы вроде «можно ли отменить»

data/
  remote/       ApiService (контракт), ApiFactory (OkHttp + токены),
                Calls (HTTP → Result), DtoMapper (DTO → домен), dto/Dtos
  local/        TokenStorage — токены в EncryptedSharedPreferences
  ws/           DraftSocket — живой статус черновика
  repository/   AuthRepository, BookingRepository

util/         Result, ApiError, Formats
AppContainer  сборка зависимостей вручную
```

### Решения, которые стоит понимать

**DTO и домен разделены.** Транспортный формат принадлежит серверу: деньги
приходят строками, даты — ISO-8601, поля могут переименоваться. Экраны зависят
от смысла, а не от сериализации. Всё преобразование — в `DtoMapper`, одном месте.

**Ошибки не бросаются, а возвращаются.** Репозиторий отдаёт `Result` — либо
значение, либо `ApiError`. «Забыть обработать ошибку» нельзя: она в типе.
Решения принимаются по машиночитаемому `code` (`slot_taken`, `draft_expired`),
а не по тексту — тексты на сервере правят без релиза приложения.

**Порядок записи задаёт сервер.** Он держит таймер на пять минут, резервирует
слот с канистрой и на каждом шаге возвращает полное состояние черновика.
Приложение это не дублирует: `nextAction` из ответа решает, какой шаг рисовать.

**Таймер на экране только рисует секунды.** Когда счётчик дошёл до нуля,
состояние перечитывается с сервера, а не считается истёкшим самостоятельно:
часы на телефоне могут отставать, а правда — на сервере.

**WebSocket только ускоряет.** То же состояние доступно через REST. Если канал
недоступен — в корпоративной сети, за прокси — экран продолжает работать, и
ошибки соединения пользователю не показываются.

**Кнопка отмены — по флагу сервера.** `can_cancel` уже учитывает дедлайн в час
до визита. Считать его на клиенте — показать кнопку, которая вернёт 409.

**Время визита — в часовом поясе точки**, а не телефона. Клиент мог уехать в
другой регион, но приезжать ему к местному времени сервиса.

**Зависимости собираются вручную** в `AppContainer`, без Hilt: граф плоский и
читается без знания аннотаций. Когда модулей станет больше, замена на Hilt
не заденет экраны — они видят только репозитории.

## Безопасность

| Что | Как сделано | Почему |
|---|---|---|
| Токены | `EncryptedSharedPreferences` (security-crypto 1.0.0), ключ в Android Keystore | На рутованном телефоне обычный XML читается как открытый текст, а refresh живёт 30 дней |
| Открытый HTTP | Запрещён (`cleartextTrafficPermitted=false`), исключение — только `10.0.2.2` в debug | По каналу ходят JWT и телефон клиента |
| Обновление сессии | Молча по refresh при 401, ровно один повтор, под общим замком | Иначе приложение через час начнёт сыпать ошибками; замок — чтобы параллельные запросы не сожгли ротируемый refresh |
| Логи | `HttpLoggingInterceptor` только в debug, вызовы `Log.*` вырезаются R8 из релиза | В логи легко утекают токены, телефоны и коды из SMS |
| Резервные копии | `allowBackup="false"` плюс явные правила исключения | Токены не должны уезжать в облако и на чужое устройство |
| Обфускация | R8 (`minifyEnabled`), DTO и Retrofit исключены правилами | Меньше вес и хуже читается при разборе APK |
| Ключ подписи | Только из `~/.gradle/gradle.properties` или секретов CI | Утечка upload-ключа = чужие обновления вашего приложения |
| Код из SMS на экране | Показывается только в debug-сборке | Чужой код не должен светиться в интерфейсе |

Проверьте перед релизом: `API_BASE_URL` и `WS_BASE_URL` — обязательно `https`
и `wss`.

Взята стабильная `security-crypto:1.0.0`. Её `MasterKeys` помечен устаревшим, а
пришедший на смену `MasterKey.Builder` живёт только в ветке `1.1.0-alpha` —
тянуть альфу в приложение для Play не стоит. Переход на стабильную `1.1.x`
затронет три строки в `TokenStorage`.

Если нужен более жёсткий контур, следующий шаг — **certificate pinning**
(`CertificatePinner` в `ApiFactory`). Не включил намеренно: при смене
сертификата без обновления приложения все клиенты разом теряют связь, и вводить
это стоит осознанно, вместе с планом ротации.

## Стиль и дизайн

Палитра и типографика повторяют лендинг — человек, пришедший с сайта, должен
узнать приложение:

- графит `#101215`, оранжевый `#E8590C` (в тёмной теме `#FF7A2F`);
- экран входа — тот же тёмный первый экран с радиальным свечением;
- жирные заголовки с плотным трекингом, надзаголовки капсом с разрядкой;
- скругления 10–18 dp, карточки с рамкой вместо теней.

Поле телефона ведёт маска `+7 (900) 111-22-33` (`PhoneInputFormatter`): префикс
не стирается, вставка из буфера разбирается в любом написании, кнопка активна
только на полном номере. Свой форматтер, а не системный
`PhoneNumberFormattingTextWatcher`: тот зависит от локали устройства, и номер
выглядел бы у разных людей по-разному. Код из SMS отправляется на проверку сам,
как только набран целиком.

Тёмная тема поддержана через `values-night`. Все тексты — в `strings.xml`:
формулировки читает клиент, и правит их не программист.

## Сборка релиза и публикация в Google Play

### 1. Ключ подписи

Создайте **upload-ключ** (один раз; потерять его — значит потерять возможность
обновлять приложение):

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Храните файл вне репозитория. Пропишите в `~/.gradle/gradle.properties`:

```properties
RELEASE_STORE_FILE=/абсолютный/путь/upload-keystore.jks
RELEASE_STORE_PASSWORD=...
RELEASE_KEY_ALIAS=upload
RELEASE_KEY_PASSWORD=...
```

В Play Console включите **Play App Signing**: Google хранит ключ подписи
приложения, а вы подписываете загрузки upload-ключом — его можно перевыпустить,
если он утечёт.

### 2. Боевой адрес API

В `app/build.gradle`, блок `release`, уже прописан боевой домен
`https://moiservis.pro/` (и `wss://` для канала). Это основной домен, а не один
из редиректящих на него (`ekspres-zamena.ru`, `экспрес-замена.рф`) — разница
принципиальна: браузер редирект отработает, а OkHttp с JWT в заголовке пойдёт
по указанному адресу и получит `301`.

Убедитесь, что на сервере:

- `DEBUG=False` и `OTP_DEBUG_EXPOSE_CODE=False`;
- `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS` и `CSRF_TRUSTED_ORIGINS` — конкретные
  домены;
- работает HTTPS перед daphne.

### 3. Сборка

```bash
./gradlew clean bundleRelease
```

Готовый файл: `app/build/outputs/bundle/release/app-release.aab` — именно `.aab`
загружается в Play Console (APK там больше не принимают).

Перед загрузкой прогоните релизную сборку на устройстве: R8 иногда вырезает то,
что нужно в рантайме, и увидеть это можно только на собранном релизе.

```bash
./gradlew installRelease
```

### 4. Что понадобится в Play Console

- **versionCode** обязан расти с каждой загрузкой (сейчас `1`).
- **Политика конфиденциальности** — обязательна, потому что приложение
  собирает телефон и данные автомобиля. Нужен публичный URL.
- **Data Safety** — заполните честно: собираются номер телефона (для входа),
  имя, марка и госномер автомобиля; данные передаются на ваш сервер, шифруются
  при передаче, удаляются по запросу.
- **Разрешения**: только `INTERNET` и `ACCESS_NETWORK_STATE` — объяснять
  ничего не придётся.
- **Скриншоты**: минимум 2 для телефона, плюс иконка 512×512 и баннер 1024×500.
- **Целевая аудитория**: не для детей.

Иконка сейчас — векторная заглушка (капля масла на оранжевом фоне) в
`res/drawable/ic_launcher_foreground.xml`. Для магазина понадобится нормальный
логотип: замените этот файл и цвет в `values/ic_launcher_background.xml`, плюс
загрузите PNG 512×512 в консоли.

## Приглашения и ссылки

Экран «Бонусы» показывает код приглашения, QR-код со ссылкой на него,
баланс баллов и две вкладки — история начислений и кто пришёл по коду.
Проценты и линии считает сервер: вторая версия правил начисления на
клиенте неизбежно разошлась бы с первой, и спорить с клиентом пришлось бы
о цифрах.

**QR рисуется на устройстве** (`util/Qr`, zxing `core`). Это единственная
сторонняя библиотека, добавленная ради одной функции, и это оправдано:
кодирование QR — коды Рида — Соломона, маски и таблицы версий, полтысячи
строк математики, в которой ошибка не видна глазом. Не нарисовался —
картинка и подпись прячутся, код и кнопка «Поделиться» рядом, экран
остаётся рабочим.

**Ссылка вида `https://moiservis.pro/i/ABC123`** открывается приложением
через Android App Links: `InviteActivity` забирает код из адреса, кладёт
его в `InviteStorage` и уходит на вход или на главный экран. Своего экрана
у неё нет — лишний шаг между нажатием на ссылку и результатом не нужен.
Код сохраняется, а не передаётся дальше в `Intent`: между переходом по
ссылке и привязкой стоит вход по SMS, и приложение по дороге может быть
выгружено системой.

Чтобы система открывала ссылку в приложении, а не в браузере, сервер
обязан отдавать `/.well-known/assetlinks.json` с SHA-256 отпечатком
подписи именно этой сборки (`ANDROID_CERT_FINGERPRINTS` в `.env` сервера).
**В отладочной сборке автопроверка не пройдёт** — подпись другая; ссылка
откроется в браузере, на странице с кодом. Так и задумано: страница на
сайте рассчитана ровно на тех, у кого приложения ещё нет.

Привязка одноразовая. Ввести чужой код можно на знакомстве после первого
входа или позже на экране «Бонусы», пока привязки нет — дальше поле
исчезает, потому что сервер всё равно ответит отказом.

## Код входа уведомлением (временно)

Пока у SMS-шлюза не согласован буквенный отправитель, SMS не уходят и
войти в приложение на живом сервере нельзя. На это время сервер
возвращает код прямо в ответе API — но только номерам из
`OTP_DEBUG_PHONES` в своём `.env`, — а приложение показывает его
уведомлением (`util/LoginCodeNotice`).

**Это не push.** Уведомление местное: приложение рисует его само, получив
код в ответе на свой же запрос. Настоящие push через FCM — отдельная
работа, и когда она появится, этот класс уйдёт вместе с заглушкой.

Заглушка живёт только в отладочной сборке: класс проверяет
`BuildConfig.DEBUG`, а разрешение `POST_NOTIFICATIONS` объявлено в
`src/debug/AndroidManifest.xml`. В релизной сборке ни разрешения, ни
уведомлений нет — лишнее разрешение в магазине пришлось бы ещё и
объяснять в анкете Data Safety.

Отказ в разрешении ничего не ломает: код виден прямо на экране входа и
подставляется в поле автоматически.

## Тесты

```bash
./gradlew testDebugUnitTest -PBUILD_DIR=C:/dev/asbuild   # путь с кириллицей
./gradlew testDebugUnitTest                              # обычный путь
```

`PhoneFormatTest` — 13 тестов на разбор и форматирование номера. Маска — тот
код, где ошибка не падает, а тихо портит ввод: первый же баг был в том, что
префикс «+7» попадал в номер первой цифрой, и семёрка «не удалялась». Глазами
при беглой проверке такое не видно, поэтому логика разбора вынесена в
`util/PhoneFormat` — без единой ссылки на Android, чтобы её можно было гонять
обычными JUnit-тестами.

## Что стоит доделать

Осознанно не вошло:

1. **Push-уведомления (FCM)** вместо SMS-напоминаний. На сервере поле
   `channel` в модели уведомлений уже есть.
2. **Автоматическое чтение кода из SMS** (SMS Retriever API) — сейчас код
   набирается руками. Нужна доработка формата SMS на сервере: код должен
   приходить с хешем приложения.
3. **Certificate pinning** — вместе с планом ротации сертификата.
4. **Офлайн-кеш списка записей** (Room): сейчас при потере связи список пуст.
5. **Тесты**: юнит-тесты на `Formats` и `DtoMapper` (чистые функции,
   тестируются без Android, как уже сделано для `PhoneFormat`),
   инструментальные — на сценарий записи и на выбор автомобиля.
6. **Списание баллов при расчёте** — это экран мастера, а не клиента:
   `points.spend()` на сервере написан, эндпоинта и кнопки нет.
7. **Поиск автомобиля не прощает опечаток и склонений.** «вест» находит
   Lada Vesta, «весту» — нет. Лечится триграммами в PostgreSQL на стороне
   сервера, браться стоит, когда станет видно, что люди промахиваются.
8. **Приложение мастера** — отдельный модуль на том же слое данных:
   `/api/v1/master/…` и канал `ws/master/` на сервере готовы.
