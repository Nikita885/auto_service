# Приложение клиента под Android — оболочка над `/app/`

С версии 2.0 приложение — тонкая нативная оболочка (WebView) над тем же
веб-приложением `/app/`, что ставится на iPhone. Экраны клиента — вход,
запись, мои записи, бонусы, профиль с машинами и всё, что появится дальше, —
пишутся один раз в вебе и на обеих платформах совпадают по построению.
Java, без Kotlin, без сторонних библиотек сверх AndroidX и Install Referrer.

**Минимум:** Android 7.0 (API 24). **Собирается под:** API 35.

## Почему оболочка

До версии 2.0 это был нативный клиент на Java (MVVM, Retrofit), и к
осени 2026 он уже расходился с веб-приложением iPhone: другие отступы,
шрифты, тексты, своя копия каждого экрана. Впереди были гараж, выбор
услуги и новый мастер записи — то есть каждый экран писать дважды и потом
сверять. Заказчик выбрал оболочку (октябрь 2026).

Что за это платим и почему это приемлемо:

- **Без сети приложение не откроется с нуля.** Service worker
  веб-приложения кеширует оболочку экранов, поэтому повторный запуск без
  сети показывает интерфейс, а не пустоту; совсем без кеша оболочка
  показывает свой экран «Нет связи с сервером» с кнопкой «Повторить».
- **Прокрутка на дешёвых телефонах чуть хуже нативной.** Экраны лёгкие
  (Preact без сборщика, ~13 КБ библиотеки), на эмуляторе разницы не видно.
- **Google Play строже к «сайту в обёртке».** Снимается тем, что у
  приложения есть нативные функции: ссылки-приглашения, Install Referrer,
  хранение токенов в Keystore, камера, системное «Поделиться»; дальше —
  push-уведомления.

TWA (Trusted Web Activity) не подошла: без проверенного отпечатка подписи
на сервере она показывает адресную строку Chrome, а `ANDROID_CERT_FINGERPRINTS`
пока пуст.

## Быстрый старт

**Нужен JDK 17 или 21.** Gradle 8.9 новее 22 не понимает:

```bash
export JAVA_HOME=~/.jdks/temurin-21
```

Откройте в Android Studio папку `mobile/android` (именно её, а не корень
репозитория).

### Кириллица в пути

Репозиторий лежит по пути `…/автосервис/…`. Сборка проходит
(`android.overridePathCheck=true` в `gradle.properties`), а юнит-тесты
падают с `ClassNotFoundException`: загрузчик тестов не находит классы по
такому пути. Проще всего — временная буква диска, она ничего не создаёт на
диске и снимается одной командой:

```
subst Y: "F:\автосервис\auto_service\mobile\android"
Y: && gradlew assembleDebug testDebugUnitTest lintDebug -PDEBUG_API_URL=https://moi-servis.ru/
subst Y: /D
```

Флаг `-PBUILD_DIR=C:/dev/asbuild` выносит каталог сборки — тоже рабочий
обход.

### Адрес сервера

Оболочка открывает `<адрес>/app/`. В отладочной сборке адрес задаётся
снаружи, без правки кода:

| Где тестируете | Флаг |
|---|---|
| боевой сервер | `-PDEBUG_API_URL=https://moi-servis.ru/` |
| эмулятор и dev-сервер на компьютере | `-PDEBUG_API_URL=http://localhost:8000/` и `adb reverse tcp:8000 tcp:8000` |
| телефон в той же сети | `-PDEBUG_API_URL=http://192.168.1.10:8000/` |

**`localhost` через `adb reverse`, а не `10.0.2.2`.** Страница по
`http://10.0.2.2` для браузера незащищённая: у неё нет камеры
(`navigator.mediaDevices`) и service worker — сканер QR и кеш не
проверить. `localhost` браузер считает защищённым даже по http.

Открытый HTTP разрешён только в отладочной сборке
(`src/debug/res/xml/network_security_config.xml`); в релизе — только https.
`DEBUG_WS_URL` больше не нужен: канал живого статуса открывает страница.

## Что делает оболочка

```
shell/ShellActivity   WebView во весь экран: настройки, отступы, «Назад»,
                      камера, «нет связи», заставка
shell/NativeBridge    window.MoiServisNative — мост страницы к приложению
shell/ShellPolicy     что своё: адреса и ключи хранилища (без Android, под тестами)
shell/InviteActivity  ссылка /i/<код> (App Links): отложить код, открыть оболочку
data/local/           TokenStorage (Keystore), InviteStorage (код приглашения)
util/                 InstallReferrer (код из Google Play), InviteCodes (разбор кода)
```

- **Страница под системными панелями, как на iPhone.** Приложение рисуется
  edge-to-edge, отступы строки состояния и навигации оболочка отдаёт
  странице (`insets()` в мосте, событие `nativeinsets`), а `app.css` берёт
  их раньше `env(safe-area-inset-*)`: в WebView `env()` всегда ноль.
  Клавиатура поднимает страницу на свою высоту (отступ корня), нижний
  отступ навигации при этом обнуляется.
- **Своё открывается внутри, остальное — системой.** Внутри только
  `<сайт>/app/…`; `tel:` уходит в звонилку, витрина, карты и чужие ссылки —
  в браузер. Сравнение по разобранному адресу (`ShellPolicy`), а не по
  началу строки: `https://moi-servis.ru.evil.example/app/` своим не
  считается.
- **«Назад»** сначала спрашивает страницу (`window.__nativeBack`): закрыть
  окно, сканер, вернуться на первую вкладку. Страница ответила `false` —
  выходим, как из любого приложения с первого экрана.
- **Камера** — для сканера QR в веб-приложении (`getUserMedia` + jsQR).
  Оболочка спрашивает системное разрешение только когда страница его
  попросила и только для своей страницы.
- **«Поделиться» и буфер обмена** — через мост: `navigator.share` в WebView
  нет, `navigator.clipboard` работает не везде.
- **Размер шрифта — как в вёрстке** (`textZoom 100`), иначе одни и те же
  экраны на Android и iPhone разъезжались бы.
- **Заставка** держится, пока страница не нарисовала первый кадр (не
  дольше 4 секунд).
- **Ярлык на рабочем столе** — `activity-alias` под прежним именем
  `.ui.auth.AuthActivity`: так звалась стартовая активность нативного
  клиента, и после обновления ярлык не превращается в «приложение не
  установлено».
- **Строка браузера** дополнена `MoiServisAndroid/<версия>` — по ней видно
  в логах nginx, сколько запросов из приложения.

### Мост `window.MoiServisNative`

| Метод | Что делает |
|---|---|
| `getItem`, `setItem`, `removeItem` | хранилище токенов — интерфейс localStorage, `core.js` подставляет его вместо `localStorage` |
| `pendingInvite()`, `clearInvite()` | отложенный код приглашения (ссылка, Google Play) |
| `share(text)`, `copy(text)` | системное «Поделиться», буфер обмена |
| `insets()` | отступы под системные панели, CSS-пиксели |

Страница узнаёт, что она в оболочке, по наличию моста (`isAndroidShell()` в
`app/lib.js`): проверка «только iPhone с главного экрана» в оболочке не
действует.

## Безопасность

| Что | Как сделано | Почему |
|---|---|---|
| Токены | `EncryptedSharedPreferences` (ключ в Android Keystore) через мост, а не localStorage WebView | на рутованном телефоне localStorage читается как открытый текст, а refresh живёт 30 дней |
| Мост | каждый метод проверяет, что открыт свой адрес (`trusted`); чужие адреса в оболочке не открываются вовсе | `addJavascriptInterface` виден любой странице в WebView |
| Хранилище моста | отдаёт только `client.access` и `client.refresh` | странице больше нечего хранить в Keystore |
| Файлы | `setAllowFileAccess(false)`, `setAllowContentAccess(false)` | странице не нужны файлы устройства |
| Открытый HTTP | запрещён в релизе | по каналу ходят JWT и телефон |
| Резервные копии | `allowBackup="false"` плюс правила исключения | токены не должны уезжать в облако и на чужое устройство |
| Отладка WebView | только в debug (`setWebContentsDebuggingEnabled`) | в релизе страницу не открыть в DevTools |
| Обфускация | R8; методы моста сохранены правилом | переименованный метод моста молча ломает страницу |

Файл и ключи хранилища токенов те же, что у нативного клиента 1.x: после
обновления человек остаётся в аккаунте.

## Приглашения и ссылки

Код не вводится руками ни в одном сценарии:

| Сценарий | Что происходит |
|---|---|
| Ссылка `/i/<код>`, приложение стоит | App Links → `InviteActivity` откладывает код → оболочка; страница отдаёт его серверу при входе, а вошедшего привязывает сразу (событие `nativeinvite`) |
| Ссылка, приложения нет | сайт ведёт в Google Play с `referrer=invite=<код>`; после установки `InstallReferrer` откладывает код, дальше так же |
| QR друга | сканер в веб-приложении |

**App Links работают только при заполненном `ANDROID_CERT_FINGERPRINTS`**
на сервере (SHA-256 подписи релизной сборки): система проверяет
`/.well-known/assetlinks.json`, и без него ссылка откроется в браузере, на
странице с кодом. В отладочной сборке подпись другая — проверка не
пройдёт, это ожидаемо. Домен в манифесте один — основной (`invite_host`):
за редиректами проверка не ходит.

## Сборка релиза и публикация в Google Play

### 1. Ключ подписи

Создайте **upload-ключ** (один раз; потерять его — значит потерять
возможность обновлять приложение):

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Храните файл вне репозитория. Пропишите в `~/.gradle/gradle.properties`:

```properties
RELEASE_STORE_FILE=/абсолютный/путь/upload-keystore.jks
RELEASE_STORE_PASSWORD=...
RELEASE_KEY_ALIAS=upload
RELEASE_KEY_PASSWORD=...
```

В Play Console включите **Play App Signing**. Отпечаток SHA-256 ключа
подписи приложения (Play Console → Целостность приложения) — в
`ANDROID_CERT_FINGERPRINTS` на сервере, иначе ссылки-приглашения не будут
открывать приложение.

### 2. Адрес сайта

В блоке `release` файла `app/build.gradle` — `https://moi-servis.ru/`.
Именно основной домен: оболочка пускает к мосту только свой домен, а после
`301` с редиректящего страница оказалась бы «чужой».

### 3. Сборка

```bash
./gradlew clean bundleRelease
```

Готовый файл — `app/build/outputs/bundle/release/app-release.aab`. Перед
загрузкой прогоните релизную сборку на устройстве (`./gradlew
installRelease`): R8 мог вырезать то, что нужно в рантайме.

### 4. Что понадобится в Play Console

- **versionCode** растёт с каждой загрузкой (сейчас `2`).
- **Политика конфиденциальности** — публичный URL, приложение собирает
  телефон и данные автомобиля.
- **Data Safety**: номер телефона (вход), имя, автомобили; данные уходят на
  ваш сервер, шифруются при передаче, удаляются по запросу.
- **Разрешения**: `INTERNET` и `CAMERA` (необязательная, только сканер QR).
- **Скриншоты**: минимум 2 для телефона, иконка 512×512, баннер 1024×500.

## Тесты и проверка

```bash
./gradlew testDebugUnitTest
```

- `ShellPolicyTest` — какие адреса свои: веб-приложение на своём домене,
  схеме и порту; витрина, `/i/<код>`, двойники домена, `http` вместо
  `https`, чужой порт, `tel:` и `javascript:` — чужие; в Keystore уходят
  только токены клиента. Ошибка здесь не падает, а тихо отдаёт мост чужой
  странице — поэтому правила вынесены из Android и гоняются обычным JUnit.
- `InviteCodesTest` — разбор кода из ссылки, QR и ответа Google Play.

Остальное проверяется в эмуляторе (Android SDK, AVD API 36): вход, токены в
`shared_prefs/auth_tokens.xml` зашифрованы и в хранилище WebView их нет,
«Назад» закрывает окно и сканер и выходит с первой вкладки, приглашение по
ссылке при открытом приложении, «Поделиться», камера с запросом
разрешения, «Нет связи» и «Повторить».

**Эмулятор на этой машине стартует только с холодной загрузки**
(`emulator -avd … -no-snapshot`): со снимка он падает с `WHPX: Unexpected
VP exit code 4`. Ширина экрана для сверки с iPhone (390 pt) — `adb shell
wm density 443` на AVD 1080×2400.

## Что стоит доделать

1. **Push-уведомления (FCM)** — нативный слой готов их принять; на сервере
   поле `channel` в модели уведомлений уже есть.
2. **Единые иконки** iPhone и Android из одного исходника знака
   (этап «единый дизайн»): сейчас иконка запуска нарисована отдельно.
3. **Встроенный шрифт** в веб-приложении: сейчас на Android — Roboto, на
   iPhone — San Francisco, остальное совпадает.
4. **Certificate pinning** — вместе с планом ротации сертификата.
