# Рабочее место мастера, версия 2.0.1

Цель: **1С:Предприятие 8.5.1.1529**, «Автосервис» **3.0.14.159** из выгрузки
`F:\git-new`. Это новая обработка с прямым подключением к серверу записи.
Для запуска нужны **обе части обновления: сервер проекта и файл EPF**.
Один новый EPF со старым сервером работать не будет: новые адреса API вернут 404.

## Исправление 2.0.1

Исправлена ошибка инициализации формы из report.json: конструктору даты
передаются все шесть компонентов. URL-декодирование команд перенесено на сервер,
поскольку в тонком клиенте эти функции недоступны. Для перехода с 2.0 заменяется
только EPF; сервер и миграции повторно обновлять не нужно. Проверка загрузки
конфигурации и проверки модулей теперь выполняется отдельными запусками.

## Что изменилось

- Слева записи выбранной точки и даты, справа несколько открытых заказов.
  Вкладки сохраняют несохранённые изменения при переключении.
- Клиент и телефон берутся с сервера. Машина, госномер, VIN и пробег уточняются
  в карточке. Госномер и VIN необязательны.
- В раскрывающемся разделе записи можно изменить услугу, время и комментарий,
  посмотреть свободные слоты. Изменение сразу отправляется в существующее API
  мастера; действуют его проверки, права точек и история изменений.
- Есть запись клиента по телефону, поиск клиента, взятие в работу, отмена с
  причиной и отметка неявки. Отмена использует штатные уведомления проекта.
- Две подписанные таблицы: **«Работы»** и **«Товары и расходные материалы»**.
  Подбор по наименованию/артикулу из 1С, редактирование количества и цены.
  Итог после записи берётся из документа с учётом его НДС и скидок.
- «Сохранить без проведения» записывает заказ-наряд и состав обслуживания на
  сервер. «К расчёту» также сохраняет заказ, чтобы показать точную сумму 1С.
  **Заказ-наряд нигде не проводится обработкой.** Его проводит бухгалтер.
- Наличные, карта, смешанная оплата; баллы — скидка по правилам сайта.
  При смешанной оплате два платёжных документа и один фискальный чек с
  работами и товарами. Платёжные документы проводятся для учёта оплаты.
- После подтверждённого чека сервер завершает запись штатным сервисом,
  списывает баллы один раз и передаёт клиенту состав работ, материалы,
  рекомендации, итог, баллы, денежную оплату и номер чека. В `/app/` это видно
  в истории. Цены незавершённых записей клиенту по-прежнему не выдаются.

## Установка сервера

Изменения подготовлены локально. Автоматического выкатывания на
`moi-servis.ru` и отправки в GitHub не выполнялось.

1. Внести код из ветки/патча в серверный checkout. Патч рассчитан на исходную
   версию `25b1ca5`; сначала `git apply --check server.patch`. Если код сервера
   уже отличается, переносить изменения с просмотром конфликтов.
2. Сделать резервную копию PostgreSQL штатным `deploy/backup.sh`. На время
   переключения завершить текущие расчёты старым способом.
3. Выполнить обычное обновление проекта из корня checkout:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
   docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api python manage.py migrate
   docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api python manage.py check
   ```

   `entrypoint.sh` также применяет миграции при старте. Новая миграция —
   `onec.0002_workplaceorder`: добавляет отдельную таблицу, не переносит и не
   удаляет старые записи/баллы. Пересборка статики нужна для истории клиента
   и выполняется штатным entrypoint.
4. Проверить вход сотрудника и `GET /api/v1/onec/workplace/bookings/<id>/order/`
   с его JWT. Ответ `{"order": null}` до первого сохранения — нормальный.
   Запрос без входа должен дать 401, клиентская учётная запись — 403.

Новые секреты и зависимости сервера не требуются. `ONEC_API_KEY` относится к
старому фоновому обмену; для нового рабочего места используется телефон и
пароль сотрудника, затем JWT и штатное обновление access-токена.

## Установка в 1С

1. Первую проверку выполнить на копии рабочей базы на компьютере с 8.5.1.1529.
   Предоставленный ранее `1Cv8.1CD` не содержал конфигурацию автосервиса;
   он не использовался как подтверждение работы в вашей базе.
2. Открыть `МойСервисРабочееМесто.epf` через «Файл → Открыть» либо добавить
   как дополнительную обработку. Обработке нужны обычные права на документы
   и справочники, HTTPS и подключаемое оборудование. Конфигурация не изменяется.
3. Ввести `https://moi-servis.ru`, телефон и пароль сотрудника, выбрать точку.
   Пароль и токены не сохраняются в HTML или общих настройках.
4. В «Настройках» сопоставить точку сайта с реквизитами 1С: цех, организация,
   платный вид ремонта, касса наличных, касса ККТ, эквайринговый терминал,
   вид платёжной карты, виды цен работ и товаров. Настройки сохраняются для
   пользователя 1С. Второму пользователю 1С сопоставление нужно заполнить тоже.
5. Выбрать **уже настроенные** АТОЛ 35Ф и терминал Unitodi P8 Bio. Используются
   штатные методы подключаемого оборудования конфигурации; прямого обращения
   к драйверам АТОЛ/банка из HTML нет.
6. На время проверки нового рабочего места остановить старый автоматический
   обмен для тех же записей. У него другая модель завершения заказа: он мог
   завершать запись по состоянию заказ-наряда до нового расчёта.

Остаток в 1С не ограничивает обычную запись заказа. Штатные проверки состава
фискального чека и маркировки сохранены. Если конфигурация требует данные,
которых нет, она может запретить чек — это нельзя считать успешной оплатой.

Список обновляется кнопкой «Обновить» и при смене даты/точки. Фонового
WebSocket-подключения в этой версии EPF нет. Перед закрытием вкладки/обработки
нужно сохранить изменения; черновики вкладок живут в открытой форме.

## Повторы и восстановление

Каждый расчёт имеет `checkout_id`. Сервер фиксирует этап до команды оборудованию,
резервирует баллы и блокирует правку записи. Повтор HTTP-ответа не даёт повторного
разрешения на списание/чек. Резерв баллов списывается в журнал только после чека.

- «Отменить подготовленный расчёт» доступно, пока оборудование ещё не запускалось.
  Убирается резерв баллов, восстанавливается сумма заказа, черновики платежей
  помечаются на удаление. Фактический возврат денег эта команда не выполняет.
- При потере связи после успешной операции нажать «Перечитать», затем
  «Продолжить расчёт». Обработка использует сохранённый в 1С RRN или номер чека.
- При неизвестном результате повтор запрещён до сверки. Сначала проверить
  журнал терминала и ККТ. Для администратора есть служебная команда на сервере:

  ```bash
  python manage.py onec_reconcile UUID_ЗАПИСИ
  ```

  Без дополнительных параметров она только показывает состояние и журнал.
  После документально подтверждённой сверки:

  ```bash
  python manage.py onec_reconcile UUID_ЗАПИСИ --actor UUID_АДМИНИСТРАТОРА --checkout-id UUID_РАСЧЕТА --revision ТЕКУЩАЯ_РЕВИЗИЯ --outcome not-charged --evidence "По журналу терминала операция отклонена, списания нет"
  ```

  Возможные результаты: `not-charged` — банк подтвердил отсутствие списания;
  `bank-confirmed --bank-reference RRN` — банк подтвердил оплату;
  `no-receipt` — в ККТ точно нет чека, можно продолжить его регистрацию;
  `receipt --receipt-number НОМЕР --shift СМЕНА` — существующий чек подтверждён.
  Команда не обращается к оборудованию и не изменяет базу 1С. Перед вариантом
  `receipt` нужно также сверить/внести номер чека в штатные документы 1С.
  Все изменения записываются с администратором, результатом и основанием.
  Мастер эту команду выполнять от своего имени не может.

После первых реальных расчётов нельзя откатывать миграцию с удалением таблицы:
она содержит журнал расчётов и резервы баллов. Обновление исправляется вперёд
с сохранением этих данных. Возвраты и коррекции выполняются штатными средствами
1С после сверки; это рабочее место оформляет первичную оплату.

## Сборка и проверки

```powershell
python integrations/1c/workplace/build.py --out C:\build\master\src
python integrations/1c/workplace/verify_source.py --config F:\git-new --report C:\build\master\source-audit.md
& 'ПУТЬ_К_8.5.1.1529\bin\1cv8.exe' DESIGNER /F 'ПУТЬ_К_КОПИИ_БАЗЫ' /LoadExternalDataProcessorOrReportFromFiles 'C:\build\master\src\МойСервисРабочееМесто.xml' 'C:\build\master\МойСервисРабочееМесто.epf' /Out 'C:\build\master\build.log'
```

`interface.html` встраивается в EPF при сборке; рядом с обработкой его хранить
не нужно. Исходники `form/http/local/payment.bsl` объединяются генератором.
`verify_source.py` проверяет наличие метаданных и экспортов в выгрузке, но не
заменяет запуск финансового сценария. `check_interface.cjs` — браузерная проверка
HTML: требует доступный Node.js, Playwright и Chromium; путь к установленному
Chrome можно передать переменной `CHROME_PATH`. Второй аргумент команды не нужен:
`node integrations/1c/workplace/check_interface.cjs C:\build\master\ui`.

В комплекте: собранный EPF, XML-исходники, серверный патч, изображения интерфейса,
предпросмотр на демонстрационных данных и `verification.md` с границами проверки.
Физические АТОЛ/терминал и коммерческая платформа 8.5.1.1529 на этом компьютере
недоступны: успешная операция на них здесь **не подтверждена**.
